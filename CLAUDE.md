# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The organization's GitHub Pages site, served at <https://marinesensitivity.org> (`CNAME`). It is a Quarto
website with one rendered homepage (`index.qmd` + `styles.scss`) and a few static pass-through files. There
is no R, no JavaScript build, no tests and no package here, so the R-package rules in the parent
`../CLAUDE.md` do not apply to this repo.

The paths `/atlas/`, `/docs/`, `/workflows/` and `/msens/` under the same domain are **not** in this repo:
each is the project Pages site of its own repo (`../atlas`, `../docs`, `../workflows`, `../msens`). Do not
create a top-level file or folder here with one of those names.

## Commands

```bash
quarto preview        # live-reloading local server
quarto render         # build to _site/ (git-ignored)
```

- **A push to `main` is a production deploy.** `.github/workflows/publish.yml` renders and publishes to the
  `gh-pages` branch on every push to `main` (or by manual dispatch). There is no staging site; work on a
  branch and merge when it is ready (the last redesign was the `atlas-first` branch).
- In a sandboxed shell `quarto render` can fail with `PermissionDenied ... tmpdir`; set `TMPDIR` to a
  writable directory.
- After a deploy, GitHub Pages' CDN holds the old copy for about 10 minutes; add a cache-busting query
  string when confirming a change live.

## How the site is assembled

- `_quarto.yml` applies `styles.scss` on top of two Bootswatch themes (`flatly` light, `darkly` dark), so
  every change has to be checked in **both** themes. Per-theme values are CSS custom properties (`--ms-*`)
  set on `body.quarto-light` and `body.quarto-dark`; SCSS variables hold the fixed palette.
- `index.qmd` is a stack of full-bleed "bands" (hero, entry cards, data and code, methodology, about,
  releases). Most are raw `{=html}` blocks; the methodology, about and releases bands are Pandoc fenced
  divs. The full-bleed layout rule is scoped with `main.content:has(> .hero)` so that it applies to the
  homepage only.
- Quarto renders every `.md`/`.qmd` in the project, so `branding/control-grammar.md` is published as
  `/branding/control-grammar.html` with the site theme (it is linked from `branding/index.html`). A new
  Markdown file that should stay private (as this `CLAUDE.md` does) needs a `!name.md` entry under
  `project: render:` in `_quarto.yml`, or it becomes a public page.
- **Anything else is published only if it is listed under `project: resources:` in `_quarto.yml`.**
  `branding/index.html` and `stac/index.html` are hand-written standalone pages with their own inline CSS;
  they do not use the Quarto theme or `styles.scss`. The other files in `branding/` (logo PDF/PNG/SVG,
  `offshore_hub.png`) are source material and are deliberately not published.
- Analytics is the gtag snippet in `_analytics.html`, not Quarto's `google-analytics:` key. One GA4
  measurement ID is shared by every MarineSensitivity product and they are separated by `content_group`
  (`home` here). Adding the Quarto key as well would double-count page views.

## Generated file: `stac/catalog.json`

Do not edit it by hand. It is an alias of the canonical STAC root at
`file.marinesensitivity.org/stac/catalog.json`, regenerated by `stac_alias_sync()` in
`../workflows/libs/stac_alias.R` (via `msens::stac_catalog_alias()`). Run from the workflows pipeline with
`STAC_ALIAS_PUSH=1`, that function commits and pushes this repo's `main` itself, and it refuses when this
checkout is off `main` or has other staged changes. Expect `stac:` commits that no one in this repo wrote,
and keep `main` clean when a release is being published.

## Releases section of the homepage

The releases band has three groups, and a release moves between them over its life:

| Group                      | Classes                                  | Link pattern                                                                      |
| -------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| Current release            | `.timeline-current`, `.timeline-item.current` | `marinesensitivity.org/atlas/?ver=vN`, `marinesensitivity.org/docs/vN/`      |
| Pre-releases under review  | `.timeline-preview`, `.timeline-item.preview` | `preview.marinesensitivity.org/vN/atlas/`, `preview.marinesensitivity.org/docs/vN/` |
| Earlier releases           | `.timeline-history`, `.timeline-item`    | same as current                                                                   |

- Pre-releases are restricted: they live on the review host behind a reviewer sign-in, and the public Atlas
  cannot open them. A pre-release must link to `preview.marinesensitivity.org`, never to the public host.
- Links use the **release id**, which can differ from the display name: v7.1 is `v7b`, v7.2 is `v7c`.
- The current release is named in two places that must agree: `.hero-release` in the hero and the
  `.timeline-current` item.
- Atlas deep links used on the page: `?lens=species`, `?tool=report`, `?ver=vN`.

## Content and design conventions

- **Numbers and claims are fact-checked before merge.** Species counts, scores and what each service
  serves are checked against the live Atlas, the release's `versions.json` and the docs, and every public
  link is checked for a 200. Do not write a figure from memory.
- **Screenshots describe the pixels.** `images/atlas-hero.png` is 1600×1000 and the three entry-card shots
  in `images/atlas/` are 720×450 (all 16:10), captured from the live Atlas. When one is recaptured, rewrite
  its `alt` to match what is actually shown, and name the Atlas build in the commit message.
- **The page borrows the Atlas's look.** The navy, panel and gold values in `styles.scss` are copied from
  `../atlas/src/lib/brand/tokens.css`, which is the source of truth; `branding/index.html` copies the same
  tokens. Gold is reserved for the single primary action ("Open the Atlas") and the current release; teal
  (`$review`) marks pre-releases; the link accent is the Atlas's own link colour in each theme.
- **The agency is the Marine Minerals Administration (MMA)**, formerly the Bureau of Ocean Energy
  Management (BOEM); the site switched on 2026-11-12. Write MMA, and say "formerly BOEM" once where there
  is room (the About paragraph, the footer). Agency links still go to `boem.gov`, which is the agency's
  live site. The seal (`branding/mma-seal.svg`) is shown unmodified, at 72 px or more, on a plain white
  plate with a quarter of its height as clear space; `branding/index.html` has the full rules. The hero
  loads `branding/mma-seal-216.png` (57 KB, three times its 72 px display size) in place of the 897 KB
  SVG; re-render it with `rsvg-convert -w 216 -h 216 branding/mma-seal.svg` if the seal changes. The
  `mst-hero` and `mst-logo` artwork is generated by `../server/branding/make_branding.py`, never edited
  here.
- `branding/control-grammar.md` (switch / tabs / spine) is the rule set for interactive controls across
  MarineSensitivity apps. It is normative for the Atlas, so change it only together with the Atlas.
- The homepage has no JavaScript of its own; keep it that way unless asked.
- Layout is checked at 1440, 1280 and 390 px wide, in light and dark.
- Commit subjects start with the area changed: `homepage:`, `stac:`, `branding:`, `analytics:`.
